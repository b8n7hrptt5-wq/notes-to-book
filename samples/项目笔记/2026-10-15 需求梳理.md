# 需求梳理：规则配置化

## 背景

现有清洗规则写死在代码里，改一条要发一次版。改成 YAML 驱动，改完热加载。

## 规则能表达什么

- 字段级：去空格、大小写、空值填充；
- 行级：必填校验、枚举校验；
- 表级：主键唯一性、时间单调性。

## 暂不支持

跨表校验（比如订单与支付对账）这期不做，放在下一期。

```yaml
field:
  order_id: { trim: true, upper: true }
  user_id: { default: UNKNOWN }
row:
  required: [order_id, user_id, status]
  enum:
    status: [created, paid, shipped, closed]
table:
  primary_key: [order_id]
```

## 风险

规则一旦支持表达式，就变成了一门小语言，维护成本会上去。这期只做声明式，不做表达式。
